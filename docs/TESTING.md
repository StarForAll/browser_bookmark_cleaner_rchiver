# 测试与验证文档

## 1. 目标

本文档描述当前项目的自动化验证矩阵、测试目录约定和必须保留的人工作业验证点。

## 2. 当前验证状态

- 自动化验证矩阵已经冻结
- `T01` 已落地真实测试框架和命令入口
- 当前自动化测试只覆盖工程基线、manifest/页面入口和壳层结构约束
- 当前尚未建立书签图谱、浏览器同步、WebDAV 恢复等业务级测试套件
- 所有验证结果必须明确标记为 `pass / fail / not run`

## 3. 自动化验证矩阵

当前目标命令：

```bash
pnpm lint
pnpm typecheck
pnpm test
pnpm build
pnpm sonar
```

规则：

- 没有执行就写 `not run`
- 不能把目标命令写成“已通过”的事实
- Sonar 凭据通过环境变量提供
- `pnpm sonar` 是项目统一的 Sonar 命令入口

## 4. 测试目录约定

- 单元 / 应用逻辑测试：`src/**/*.test.ts`
- React 组件测试：`src/**/*.test.tsx`
- 共享 fixtures / mocks / helpers：`test/`

## 5. 推荐测试类型

### 5.1 自动化测试

以下是后续业务任务需要逐步补齐的目标测试类型，不代表当前仓库都已存在：

- 纯领域逻辑
- 图谱标准化
- 重复 URL 检测
- 草稿 patch 生成与撤销
- 适配器输入输出映射
- 组件层关键交互

### 5.2 必须人工验证的内容

- Chrome 扩展实际加载
- 浏览器书签读取与写回
- 权限申请流程
- WebDAV 连通性、上传、恢复
- 覆盖前备份与撤销覆盖
- 状态区与失败反馈

## 6. 高风险验证点

以下内容不能只靠“看起来没问题”判断：

- 浏览器写回前是否先生成浏览器备份
- 从浏览器覆盖草稿前是否先生成草稿备份
- WebDAV 恢复前是否先生成对应对象备份
- 浏览器写回失败后是否区分回滚成功 / 回滚失败
- WebDAV 未配置、未授权、不可用时相关按钮是否正确禁用
- `Ctrl+Z` 是否只影响草稿，不影响已完成的外部写操作

## 7. 测试先行输入

当前测试先行基线：

- package manager：`pnpm`
- 自动化门禁命令：`pnpm test`
- 首版不强制单独 eval 目录
- Chrome 扩展运行时行为仍需要人工验证补足

## 8. 提交前最小验证要求

至少应明确记录：

- `pnpm lint`
- `pnpm typecheck`
- `pnpm test`
- `pnpm build`
- `pnpm sonar`
- Chrome 扩展人工验证结果

每项结果都必须写成：

- `pass`
- `fail`
- `not run`

## 9. 当前缺口

当前仍缺少或尚未完成的验证能力：

- Chrome 扩展运行时人工验证
- 浏览器书签读取与写回验证
- WebDAV 连通性、上传与恢复验证
- 具体业务能力对应的测试套件

即使基线 scaffold 已落地，本文档中的自动化部分也不能被当作默认已通过，仍需按实际执行结果记录。
