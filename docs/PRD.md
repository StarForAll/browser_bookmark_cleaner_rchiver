# 产品需求文档

## 1. 产品概述

浏览器书签清理与归档器是一款 Chrome MV3 扩展。它把当前浏览器书签读取为可编辑草稿图谱，让用户在独立工作区中整理结构、发现重复 URL、显式同步回浏览器，并通过 WebDAV 保存和恢复版本化快照。

### 当前实现快照

- 已完成 Vite + React + TypeScript + pnpm 工程底座。
- 已完成 Chrome MV3 manifest、service worker、扩展图标打开 / 聚焦工作区页面。
- 已完成启动阶段“本地草稿优先恢复 -> 浏览器书签导入 -> 首次导入本地持久化”链路。
- 已完成规范化草稿图谱、节点编辑、同级 / 子级创建、删除、拖拽移动、键盘重排 / 提升、draft-only `Ctrl+Z`。
- 已完成标题 / URL 搜索、重复 URL 聚焦、悬浮详情、状态历史、禁用态说明。
- 已完成从浏览器覆盖当前草稿、同步当前草稿到浏览器书签、本地备份、撤销覆盖、WebDAV 设置 / 可用性检测 / 上传 / 恢复。
- 已建立覆盖当前主链的自动化测试；发布前仍需真实 Chrome 扩展与真实 WebDAV 服务人工验收。

## 2. 问题陈述

浏览器原生书签管理在面对大量书签、重复 URL、频繁结构调整和跨设备备份时存在明显短板：

- 层级结构不直观，难以快速理解整体书签树。
- 重复 URL 发现和处理成本高。
- 大范围移动、重命名和删除缺少草稿缓冲。
- 覆盖式整理缺少清晰的备份与撤销覆盖能力。
- 原生书签缺少用户自控的版本化归档与恢复机制。

## 3. 解决方案

首版提供一个独立扩展页面作为主工作区：

- 直接读取 Chrome 书签树并转换为草稿图谱。
- 所有编辑默认只作用于草稿，避免误改真实浏览器书签。
- 用户确认后才执行浏览器覆盖、浏览器写回、WebDAV 上传或 WebDAV 恢复。
- 覆盖式动作前自动生成对应对象的本地最新备份。
- WebDAV 保存草稿快照和浏览器书签快照，并分别保留最近 5 个版本。

## 4. 目标用户

- 长期维护大量书签的个人用户。
- 对整理效率、结构感和恢复能力有要求的重度浏览器用户。
- 希望用自有 WebDAV 存储保存书签版本，而不依赖第三方账号后端的用户。

## 5. 成功标准

- 用户可以读取当前 Chrome 书签并在图谱中查看。
- 用户可以完成节点编辑、新增、拖拽移动、删除、键盘重排和草稿撤销。
- 用户可以快速搜索标题 / URL，并聚焦重复 URL。
- 用户可以显式将草稿同步到浏览器书签。
- 用户可以把草稿或浏览器书签上传到 WebDAV，并从指定版本恢复。
- 覆盖当前草稿或浏览器书签前，系统会先生成本地单份回滚备份。
- 操作成功、失败、阻断和回滚结果都有明确中文反馈。

## 6. 产品范围

### 6.1 包含

- Chrome MV3 扩展。
- 独立扩展页面工作区。
- 浏览器书签读取、导入、覆盖草稿、写回浏览器。
- 草稿图谱编辑、搜索、重复 URL 聚焦和 draft-only 撤销。
- 本地草稿会话、撤销历史、状态历史、WebDAV 配置和本地备份持久化。
- WebDAV 上传、版本索引、版本保留、草稿恢复、浏览器书签恢复。
- 中文界面文案，并保留后续多语言扩展空间。

### 6.2 不包含

- 自建账号系统或 SaaS 后端。
- 多用户协作。
- 多选 / 批量操作。
- 复杂智能分类。
- 首版正式 Firefox 支持。
- 后台自动同步任务。

## 7. 核心用户故事

- 作为用户，我希望直接读取当前浏览器书签，而不是手动导入 HTML，这样我可以立即开始整理。
- 作为用户，我希望书签以图谱形式展示，这样我能更直观地理解层级结构。
- 作为用户，我希望整理动作先进入草稿，这样我可以确认后再同步到浏览器书签。
- 作为用户，我希望快速发现重复 URL，这样我可以减少冗余书签。
- 作为用户，我希望把草稿和浏览器书签分别上传到 WebDAV，这样我能拥有自控的云端版本。
- 作为用户，我希望覆盖前自动生成本地备份，这样误操作后还能撤销覆盖。

## 8. 功能需求

### 8.1 书签读取与草稿生成

- 读取当前 Chrome 书签树。
- 跳过浏览器结构根，只把真实受管节点转换为草稿图谱。
- 本地存在可恢复草稿时优先恢复本地草稿，不自动覆盖用户现有草稿。
- 首次导入成功后立即尝试本地持久化。

### 8.2 图谱查看与编辑

- 支持目录节点和书签节点。
- 支持单击选择、双击编辑、`Enter` 新增子节点、`Shift + Enter` 新增同级节点。
- 支持拖拽移动、`↑ / ↓` 同层重排、`←` 提升一级目录层级。
- 支持 `Delete / Backspace` 删除节点及其子树；高风险删除进入确认。
- 目录节点只编辑标题；书签节点编辑标题和 URL。

### 8.3 草稿撤销

- `Ctrl+Z` 只回退草稿编辑历史。
- 外部写操作、WebDAV 上传、WebDAV 恢复和覆盖浏览器不进入 `Ctrl+Z`。
- 草稿变更生成语义化 undo entry，并随本地草稿会话持久化。

### 8.4 搜索与重复 URL 聚焦

- 支持按标题或 URL 搜索。
- 普通搜索输入时高亮结果，按 `Enter` 后进入结果导航。
- 搜索框 `↑ / ↓` 在结果导航激活后循环切换焦点。
- “仅看重复项”切换到重复 URL 分组视图，并与当前搜索词组合工作。

### 8.5 浏览器覆盖与写回

- “从浏览器覆盖当前草稿”必须进入确认流程。
- 覆盖草稿前先生成当前草稿本地备份。
- “同步当前草稿到浏览器书签”必须进入确认流程。
- 写回浏览器前先生成当前浏览器书签本地备份。
- 浏览器写入失败时执行 best-effort rollback，并区分回滚成功 / 回滚失败。

### 8.6 WebDAV 云端能力

- 支持单一 WebDAV 配置。
- 支持保存配置、请求 host 权限、测试可用性。
- 云端动作只有在配置有效、host 权限已授予且最近一次可用性检测成功后启用。
- 草稿快照和浏览器书签快照分类型上传。
- 每类保留最近 5 个版本，恢复列表由 `index.json` 驱动。
- WebDAV 草稿版本只能恢复到当前草稿；WebDAV 书签版本只能恢复到浏览器书签。

### 8.7 本地撤销覆盖

- 草稿备份与浏览器书签备份分别只保留最新 1 份。
- “撤销覆盖操作”根据可用备份打开目标选择。
- 撤销草稿覆盖会恢复本地草稿备份。
- 撤销浏览器书签覆盖会把本地浏览器备份写回浏览器，并沿用写回回滚策略。

### 8.8 状态反馈

- 最近 3 条状态记录按时间倒序展示。
- 状态弹窗可关闭，关闭后保留重新打开入口。
- 失败记录展示可读原因，并保留技术详情。
- 敏感 WebDAV 配置不得出现在状态文案或技术详情中。

## 9. 验收标准

- Chrome 扩展可在本地加载并打开独立工作区页面。
- 首次启动可读取浏览器书签并生成草稿图谱。
- 本地草稿存在时可优先恢复本地草稿。
- 图谱编辑、搜索、重复聚焦、拖拽、键盘操作和 `Ctrl+Z` 行为符合预期。
- 浏览器覆盖草稿、同步到浏览器书签、撤销覆盖均有确认、备份和状态反馈。
- WebDAV 配置、可用性检测、上传、恢复和版本保留在真实服务上可用。
- `pnpm lint`、`pnpm typecheck`、`pnpm test`、`pnpm build` 执行结果可追溯。
- Sonar 扫描结果按实际情况记录为 `pass / fail / not run`。

## 10. 约束

- 核心能力由扩展承载，不依赖远程 URL 网页服务提供主交互。
- 浏览器 API、WebDAV 和本地持久化不得直接耦合到 React 展示组件。
- 当前业务真相是规范化草稿图谱，不是渲染层节点边对象。
- `tmp/ui/` 仅作为视觉与交互参考资产，不能复制代码进入生产实现。
- 项目不修改外部 workflow 仓库。
