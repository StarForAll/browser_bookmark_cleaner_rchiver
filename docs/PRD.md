# 产品需求文档（PRD）

## 1. 概述

### 项目名称

浏览器书签清理与归档器

### 当前状态

新增语言约束已完成补充，当前仍处于 `design` 阶段。已确认：首版前端所有用户可见内容必须以中文展示，同时产品设计与实现需要保留后续扩展为多语言支持的空间。`Step 3` 已基于现有 `tmp/ui` 完成讨论式原型验证，并明确该原型只作为视觉与交互参考资产，禁止直接复用其中代码。当前仓库不保留可信工程基座，但 `Step 5` 已冻结 React + TypeScript、Vite、节点图库方案、`@xyflow/react`、轻量集中式状态管理、原生 `fetch` WebDAV、仅扩展页面运行拓扑，以及“当前草稿完整快照 + `Ctrl+Z` patch 历史 + 周期性 checkpoint 快照”的撤销模型。架构冻结后，还必须先完成 spec 对齐、自动化检查矩阵、`test-first` 输入、`finish-work` / `record-session` 适配，并在全部完成后经人工确认，才允许进入 `plan`。

### 问题陈述

浏览器原生书签管理方式在面对大规模书签、重复 URL、频繁整理和结构调整时，交互效率低、信息密度不足，也缺少清晰的云端版本化能力。

### 解决方案

构建一个 Chrome 扩展，以独立扩展页面承载思维导图式书签管理界面。扩展直接读取当前浏览器书签，将其映射为可编辑草稿树，并通过 WebDAV 提供版本化备份、恢复与同步能力。

## 2. 成功标准

- 用户可以直接读取当前 Chrome 书签并在思维导图中查看。
- 用户可以顺滑地完成单节点编辑、新增、拖拽移动、删除和撤销。
- 用户可以将浏览器书签或思维导图草稿同步到 WebDAV，并保留最近 5 个版本。
- 用户可以从 WebDAV 覆盖恢复到浏览器书签或当前草稿，并在覆盖前自动获得本地单份回滚备份。
- 用户可以快速识别重复 URL，并通过搜索/过滤聚焦相关节点。
- 用户在首版中看到的所有前端界面文案均为中文，同时后续接入多语言时不需要推倒重做界面结构。

## 3. 产品形态

- 平台：Chrome 扩展
- 主工作区：独立扩展页面 / 新标签页
- 首版浏览器范围：Chrome
- 首版界面语言：中文
- 后续扩展：保留 Firefox 扩展空间
- 后续扩展方向：保留多语言支持空间

## 4. 用户与场景

### 目标用户

- 需要长期维护大量书签的个人用户
- 对整理效率和操作流畅度有明显要求的重度浏览器用户

### 核心场景

- 查看当前浏览器书签的整体结构
- 快速发现重复 URL
- 在图谱中直接整理书签结构
- 将整理结果显式同步回浏览器书签
- 将浏览器书签或草稿版本备份到 WebDAV
- 从云端版本恢复当前浏览器书签或当前草稿

## 5. 核心用户故事

- 作为用户，我希望直接读取当前浏览器书签，而不是手动导入 HTML，这样我可以立即开始整理。
- 作为用户，我希望书签以思维导图形式展示，这样我能更直观地理解层级结构。
- 作为用户，我希望可以双击编辑节点、拖拽移动节点、直接删除节点，这样整理过程更顺手。
- 作为用户，我希望所有修改先只作用在草稿上，这样我可以整理好之后再决定是否同步到浏览器书签。
- 作为用户，我希望可以将书签和草稿分别同步到 WebDAV，并保留最近 5 个版本，这样我能有云端备份和版本回溯能力。
- 作为用户，我希望覆盖恢复前自动生成本地回滚备份，这样误恢复后还能撤回。

## 6. 功能需求

### 6.1 书签读取与展示

- 直接读取当前 Chrome 浏览器书签树。
- 主工作区始终展示当前思维导图草稿，而不是直接把页面表达为浏览器实时书签编辑面板。
- 使用思维导图形式展示书签树。
- 支持节点折叠/展开。
- 节点展开/折叠状态本地持久化，不进入云端同步。
- 思维导图布局坐标本地持久化，不进入云端同步。
- 默认初始布局必须美观、舒适、可直接操作。
- 提供“一键自动归位”按钮，将界面恢复到推荐舒适布局。

### 6.2 节点信息与重复识别

- 节点悬浮时显示 URL 信息。
- 若存在重复 URL，悬浮层采用混合模式展示：
  - 显示重复总数
  - 直接显示前 2 条重复路径
  - 其余项通过“展开更多”查看
- 内部可使用稳定 ID 进行识别、同步和恢复，但 ID 不在界面直接展示。

### 6.3 节点编辑

- 双击节点进入编辑模式。
- 目录节点可编辑标题。
- 网页节点可编辑标题和 URL。
- 编辑已有节点时，节点类型不可修改。

### 6.4 新增节点

- 单击选中节点后，按 `Enter` 进入新增流程。
- 新增节点时，在新增表单中选择节点类型：
  - 目录节点
  - 网页节点
- 节点类型对应校验规则：
  - 目录节点不能填写 URL
  - 网页节点 URL 不能为空

### 6.5 移动与删除

- 节点支持拖拽移动到其他目录节点下。
- 节点支持直接删除，不弹二次确认框。
- 删除对象包含该节点及其子树。

### 6.6 撤销历史

- `Ctrl+Z` 只作用于思维导图草稿编辑。
- 每一次思维导图内容变化都记为一条本地历史。
- 每次按下 `Ctrl+Z` 回退一步编辑历史。
- `Ctrl+Z` 不负责回退“同步到浏览器书签”这类外部写操作。

### 6.7 操作提示可见性

- 界面左下角固定显示低干扰的“操作提示说明区”。
- 操作提示说明区默认始终可见，但视觉上不应抢占主图谱注意力。
- 操作提示说明区以“一行一条”的形式同时展示鼠标操作与键盘操作。
- 首版必须完整展示以下 6 条操作提示：
  - 单击：选中节点
  - 双击：编辑节点
  - 拖拽：移动节点
  - `Enter`：新增子节点
  - `Delete / Backspace`：删除节点
  - `Ctrl+Z`：撤销上一步编辑
- 目录节点与网页节点使用统一的操作提示体系，差异仅体现在字段校验和业务规则上。

### 6.8 搜索与聚焦

- 提供基础搜索能力，支持按标题或 URL 搜索节点并定位结果。
- 提供重复 URL 过滤 / 聚焦能力。

### 6.9 文案与语言策略

- 首版前端所有用户可见内容均使用中文展示，包括按钮、表单标签、状态提示、错误提示、空态提示、确认文案与操作提示说明。
- 文案组织方式需保留后续多语言扩展空间，避免把展示文本零散硬编码在各个组件逻辑中。
- 后续若引入多语言支持，应能在不重写核心界面结构的前提下替换或扩展文案资源。

## 7. 数据与同步模型

### 7.1 数据分层

系统至少包含以下状态层：

- 浏览器实时书签数据
- 当前思维导图草稿
- WebDAV 云端版本快照
- 本地单份回滚备份

### 7.2 草稿与浏览器写回

- 新增、编辑、移动、删除默认只作用于当前思维导图草稿。
- 不自动写回浏览器书签。
- 提供“从浏览器覆盖当前草稿”按钮；点击后必须弹出统一确认框，用户确认后才执行覆盖。
- 用户点击“同步到浏览器书签”按钮，并确认警告框后，才真正执行浏览器书签写回。

### 7.3 显式动作入口

- 右上角直接显示以下 7 个动作按钮，且用户仅通过按钮文字就能理解其含义：
  - 从浏览器覆盖当前草稿
  - 同步当前草稿到浏览器书签
  - 上传当前草稿到 WebDAV
  - 上传当前浏览器书签到 WebDAV
  - 下载 WebDAV 草稿版本到当前草稿
  - 下载 WebDAV 书签版本并覆盖浏览器书签
  - 撤销覆盖操作
- 不要求在界面上额外做“浏览器动作组 / WebDAV 动作组”的分组表达。

## 8. WebDAV 云端能力

### 8.1 配置

- 首版只支持单一 WebDAV 配置。
- WebDAV URL、用户名、密码等连接信息由用户手动填写。
- 连接信息保存在扩展本地。
- 提供“测试可用性”按钮。
- 若 WebDAV 未配置或不可用，则云端相关功能整体禁用，并提示用户先完成配置。

### 8.2 云端版本策略

- 浏览器书签同步到 WebDAV，保留最近 5 个版本。
- 思维导图草稿保存到 WebDAV，保留最近 5 个版本。
- 浏览器书签版本文件与草稿版本文件分别存储。
- 实现细节不直接暴露给用户。

### 8.3 恢复语义

- 用户通过两个独立入口分别执行恢复：
  - 下载 WebDAV 草稿版本到当前草稿
  - 下载 WebDAV 书签版本并覆盖浏览器书签
- 两类恢复都采用覆盖语义，并统一进入同一种确认框，只替换动作文案。

## 9. 本地回滚机制

- 任何覆盖式恢复执行前，必须先将当前最新状态导出到本地备份文件。
- 浏览器书签和思维导图草稿分别生成各自对应的本地单份备份文件。
- 本地只保留每一类对象的最新 1 份备份。
- 右上角提供统一的“撤销覆盖操作”入口。
- 点击“撤销覆盖操作”后，用户再二次选择恢复对象：
  - 撤销对浏览器书签的覆盖
  - 撤销对当前草稿的覆盖
- 若两类对象都没有可撤销的覆盖备份，则“撤销覆盖操作”按钮禁用，并在悬浮时说明当前没有进行覆盖操作，不能进行撤销覆盖操作。
- 若只有其中一类对象可撤销，则按钮仍可点击，但二次选择中不可用项需要禁用并说明原因。
- 用户若后悔，可基于对应对象的本地最新备份执行还原。

## 10. 反馈与状态提示

### 10.1 成功反馈

- 只有在动作执行完成后，界面右下角才显示状态结果。
- 右下角状态弹窗可关闭，关闭后仍保留“最新结果”入口，点击后可重新展开。
- 状态区保留最新 3 条历史记录，按时间倒序展示。
- 成功记录至少显示：
  - 操作描述
  - 操作时间
  - 操作结果

### 10.2 失败反馈

- 失败记录同样在动作执行完成后写入右下角状态区。
- 失败记录至少显示：
  - 操作描述
  - 操作时间
  - 操作结果
  - 简要失败原因
- 成功和失败结果都需要进入最近 3 条历史记录。

## 11. 非目标

- 多浏览器首版支持
- 多选 / 批量操作
- 自建账号系统或 SaaS 后端
- 多用户与协作
- 复杂智能分类

## 12. 约束

- 核心能力由扩展承载，不依赖远程 URL 网页服务提供核心交互。
- 首版前端展示语言固定为中文，但设计与实现必须预留后续多语言扩展空间。
- 当前项目不修改外部 workflow 仓库：
  `/ops/projects/personal/ai-coding-toolkit/docs/workflows/新项目开发工作流`

## 13. 验收标准

- 能直接读取当前 Chrome 书签树并展示为思维导图。
- 节点支持双击编辑；网页节点可编辑 URL。
- 节点支持通过 `Enter` 新增子节点。
- 节点支持拖拽移动与直接删除。
- `Ctrl+Z` 可逐步回退草稿编辑历史。
- 展开/折叠状态与布局坐标可本地持久化。
- 默认布局可用且美观，并提供一键自动归位。
- WebDAV 可配置、可测试可用性、可同步、可恢复。
- WebDAV 未配置或不可用时，云端功能禁用且有明确提示。
- 同步成功与失败均有清晰反馈。
- 左下角固定显示完整的操作提示说明区，且包含单击、双击、拖拽、`Enter`、`Delete / Backspace`、`Ctrl+Z` 这 6 条提示。
- 右上角 7 个动作按钮含义清晰，用户仅看按钮文字即可理解动作。
- 4 个覆盖型动作在执行前统一进入确认框：
  - 从浏览器覆盖当前草稿
  - 同步当前草稿到浏览器书签
  - 下载 WebDAV 草稿版本到当前草稿
  - 下载 WebDAV 书签版本并覆盖浏览器书签
- 右下角状态区保留最新 3 条成功/失败历史记录，且支持关闭后重新展开查看。
- 提供基础搜索和重复 URL 过滤 / 聚焦能力。
- 首版不包含多选/批量操作。
- 首版前端所有用户可见内容均为中文展示。
- 当前文案组织方式可支持后续多语言扩展，而不要求大规模重写界面结构。

## 14. 风险与后续设计重点

### 主要风险

- 思维导图拖拽与布局持久化的复杂度较高。
- 浏览器书签同步与本地草稿状态之间需要严格区分，避免用户误解。
- WebDAV 可用性、认证失败、写入失败等异常路径需要完整处理。

### 设计阶段重点

- 冻结扩展架构与页面承载方式
- 冻结书签数据层、草稿层、同步层的边界
- 定义 WebDAV 文件组织方式
- 定义撤销历史栈与本地回滚备份的存储结构
- 定义自动布局与手动布局共存策略
- 冻结前端文案资源组织方式与后续多语言扩展接口
