# 技术架构文档

## 1. 目标

本文档面向开发者，说明浏览器书签清理与归档器的系统边界、运行面、分层结构、关键技术选择、外部副作用策略和当前实现快照。

## 2. 系统边界

- 产品形态：Chrome MV3 扩展。
- 正式运行面：独立扩展页面。
- 扩展入口：service worker 处理扩展图标点击，打开或聚焦工作区页面。
- 云端能力：用户自带 WebDAV。
- 本地能力：`chrome.storage.local` 保存草稿会话、状态历史、WebDAV 配置和本地备份。
- 不包含：独立后端服务、数据库、账号系统、后台自动同步任务。

## 3. 架构原则

- 草稿优先编辑：当前可编辑真相是草稿图谱，不是浏览器实时书签树。
- 显式副作用：浏览器覆盖、浏览器写回、WebDAV 上传、WebDAV 恢复和撤销覆盖都必须由用户显式触发。
- 覆盖前备份：任何覆盖当前草稿或浏览器书签的动作，执行前先生成对应对象的本地最新备份。
- 串行外部动作：同一时刻只允许一个外部副作用动作运行，避免并发覆盖。
- 失败优先保草稿：外部动作失败时优先保护当前草稿，浏览器侧写入失败执行 best-effort rollback。
- 单一业务真相：规范化草稿图谱是业务真相，渲染节点、边、布局信息都是派生数据。
- 适配器隔离：React 展示层不直接调用 `chrome.*`、原始 `fetch` 或本地存储接口。

## 4. 分层结构

```text
src/
  app/                     页面装配、状态入口、工作区壳层
  features/                应用用例与功能模块
  domain/                  草稿图谱领域模型与编辑逻辑
  adapters/                Chrome bookmarks、本地持久化、WebDAV 适配器
  shared/                  文案、校验、共享工具
```

### 4.1 Extension Page

- 承载 React + TypeScript 应用。
- 负责展示、交互和页面级状态入口。
- 不直接处理原始浏览器 API、WebDAV 协议或本地存储细节。

### 4.2 Application / Use Case Layer

- 编排显式用户动作。
- 负责前置检查、确认后的执行保护、状态记录和错误收口。
- 典型模块：启动导入、WebDAV 上传、WebDAV 恢复、工作区入口。

### 4.3 Domain Layer

- 定义 `DraftGraphSnapshot`、`DraftGraphNode`、undo entry、checkpoint 等领域契约。
- 执行节点编辑、移动、删除、重排、提升等草稿内变更。
- 保持与浏览器 API、WebDAV 和 React 渲染解耦。

### 4.4 Adapter Layer

- Chrome bookmarks adapter：读取浏览器书签、导入草稿、从草稿导出浏览器树、写回受管书签范围。
- Local persistence adapter：读写草稿会话、WebDAV 配置、权限状态、本地备份。
- WebDAV adapter：JSON 文档读写、删除、可用性检测、host 权限请求。

### 4.5 Composition Root

- 在扩展页面入口完成依赖装配。
- 业务模块不得绕过装配边界分散直连底层实现。

## 5. 当前技术栈

- UI runtime：React 19 + TypeScript
- Build tool：Vite
- Package manager：`pnpm`
- Test runner：Vitest + Testing Library
- Lint：ESLint
- Extension platform：Chrome MV3
- WebDAV：原生 `fetch`

## 6. 关键运行链路

### 6.1 启动恢复

1. 优先尝试恢复本地草稿会话。
2. 本地草稿可恢复时，不再读取浏览器书签。
3. 本地草稿不存在时读取浏览器书签树。
4. 浏览器书签通过适配器校验并导入为草稿图谱。
5. 首次导入成功后立即尝试持久化草稿会话。

### 6.2 浏览器覆盖当前草稿

1. 用户点击“从浏览器覆盖当前草稿”。
2. UI 打开统一覆盖确认框。
3. 确认后先写入草稿本地备份。
4. 读取当前浏览器书签并导入为新草稿。
5. 写入本地草稿会话并记录状态结果。

### 6.3 同步草稿到浏览器书签

1. 用户点击“同步当前草稿到浏览器书签”。
2. UI 打开统一覆盖确认框。
3. 确认后读取当前浏览器书签并写入浏览器本地备份。
4. 草稿图谱导出为浏览器书签树。
5. 写回受管范围；失败时执行 best-effort rollback。

### 6.4 WebDAV 上传与恢复

- 上传草稿和上传浏览器书签使用独立类别、独立索引、独立版本文件。
- 恢复草稿前先备份当前草稿。
- 恢复浏览器书签前先备份当前浏览器书签，再写回浏览器。
- WebDAV 动作依赖有效配置、host 权限和最近一次成功可用性检测。

## 7. 图谱渲染边界

- 当前实现使用项目自有 DOM + SVG mindmap 画布渲染。
- 规范化图谱是业务真相，渲染层节点和连线是派生结果。
- 画布包含 view-only virtual root node；它不进入领域真相或持久化资产。
- 大图谱场景按视口与树宽度处理可见性和布局提示，避免渲染体验失控。
- `@xyflow/react` 是早期目标选型，但当前未接入；后续只有在能降低复杂度时才应引入。

## 9. 约束与风险

- 所有高风险外部动作必须保持显式确认。
- 敏感 WebDAV 配置不得进入普通状态文案、技术详情或测试快照。
- 浏览器写回失败必须区分普通失败、已自动回滚、自动回滚失败。
- 自动化测试不能替代真实扩展加载、真实书签写回和真实 WebDAV provider 验收。
