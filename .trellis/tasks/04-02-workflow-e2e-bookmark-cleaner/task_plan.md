# Browser Bookmark Cleaner Task Plan

## 概述

本计划基于当前已冻结的 PRD 与 `design/` 设计包，为首版 Chrome 扩展实现生成可执行任务拆解、依赖关系和执行安排。

目标主链：

1. 建立真实可运行的扩展工程底座
2. 建立浏览器书签读取 -> 草稿图谱编辑 -> 搜索/重复聚焦 -> 浏览器写回 / WebDAV 版本化 / 恢复的闭环
3. 建立最小可审计的验证门禁，确保后续 `test-first`、`start`、`finish-work`、`record-session` 都有项目化落点

当前判断：

- 项目复杂度：L2
- 产品形态：Chrome MV3 扩展 + 独立扩展页面
- 主风险：图谱交互复杂度、草稿态与浏览器写回边界、用户自定义 WebDAV endpoint 的权限与错误处理

## 前置约束与 Evidence Gap

已确认约束：

- 首版只支持 Chrome，保留后续 Firefox 扩展空间
- 主工作区运行在扩展页面，不使用 popup 作为主编辑容器
- `tmp/ui/` 仅为 UI 风格参考，不允许直接复用其中代码
- 当前界面默认语言为中文，但布局需为未来多语言扩展预留空间

[Evidence Gap]

- 当前仓库还没有真实前端工程代码，`package.json`、测试栈、lint/typecheck/build 命令尚未冻结
- 当前 `.trellis/spec/` 中大部分仍是通用占位内容，尚未完成本项目的自动化检查矩阵与 `finish-work` / `record-session` 项目化适配

处理策略：

- 在正式进入产品功能实现前，优先完成工程底座和项目化验证基线
- `test-first` 阶段以前，需要先冻结实际命令和测试目录约定

## 验收标准

- [ ] 验收：扩展可在 Chrome 中加载，并打开独立工作区页面
- [ ] 验收：能读取当前浏览器书签树并渲染为可编辑图谱
- [ ] 验收：图谱支持节点选择、双击编辑、`Enter` 新增子节点、拖拽移动、删除、`Ctrl+Z`
- [ ] 验收：本地保存草稿态、布局态、展开态、撤销历史
- [ ] 验收：支持标题 / URL 搜索与重复 URL 聚焦
- [ ] 验收：浏览器写回必须经过显式确认
- [ ] 验收：WebDAV 未配置、权限未授予或连通性失败时，云端操作整体禁用且提示原因
- [ ] 验收：能保存浏览器书签快照与草稿快照到 WebDAV，并各自保留最新 5 份
- [ ] 验收：能从 WebDAV 恢复到浏览器书签或草稿；覆盖前自动生成对应本地最新备份
- [ ] 验收：所有验证结果必须明确标注为 `pass` / `fail` / `not run`

## 依赖关系

前置任务：

- `PLAN-01` 是 `PLAN-02` 的前置任务
- `PLAN-02` 是 `PLAN-03` 的前置任务
- `PLAN-03` 是 `PLAN-04` 的前置任务
- `PLAN-04` 是 `PLAN-05` 的前置任务
- `PLAN-04`, `PLAN-05` 是 `PLAN-06` 的前置任务
- `PLAN-03`, `PLAN-05`, `PLAN-06` 是 `PLAN-07` 的前置任务
- `PLAN-02` 至 `PLAN-07` 是 `PLAN-08` 的前置任务

阻塞任务：

- `PLAN-01` 阻塞整个实现主链，因为它决定真实工程命令、目录和验证门禁
- `PLAN-02` 阻塞所有产品功能，因为后续任务没有运行壳就无法落地
- `PLAN-03` 阻塞图谱编辑、搜索、浏览器写回和 WebDAV，因为它提供统一数据模型
- `PLAN-06` 与 `PLAN-07` 共同阻塞同步/恢复验收闭环

并行任务：

- `PLAN-01A` 可与 `PLAN-01` 并行
- `PLAN-05` 中不涉及共享状态核心改造的提示组件准备，可在 `PLAN-04` 后半段作为并行子工作处理

串行主链：

- `PLAN-01` → `PLAN-02` → `PLAN-03` → `PLAN-04` → `PLAN-05` → `PLAN-06` → `PLAN-07` → `PLAN-08`

可并行候选说明：

- `PLAN-01A` UI 参考资产回写可以与 `PLAN-01` 中的工程基线冻结并行
- `PLAN-05` 的状态栏 / 提示组件准备，可在 `PLAN-04` 后半段与部分 WebDAV 文档接口准备并行
- `PLAN-07` 不能早于 `PLAN-03`，因为它依赖已存在的草稿快照和恢复对象模型

关键依赖：

- 没有 `PLAN-01`，就没有可执行测试矩阵与项目化 workflow 门禁
- 没有 `PLAN-02`，后续所有功能都没有实际运行壳
- 没有 `PLAN-03`，图谱编辑、搜索、浏览器写回和 WebDAV 都没有统一数据模型
- 没有 `PLAN-06` / `PLAN-07`，就无法满足设计里明确的同步与恢复语义

## 任务明细（DoR / DoD）

### PLAN-01 冻结工程底座与项目化验证基线

范围：

- 冻结包管理器、依赖管理方式、扩展工程目录、lint/typecheck/test/build 命令
- 明确 `test-first` 阶段将使用的真实命令与测试文件目录
- 首次项目化适配 `.trellis/spec/`、`finish-work`、`record-session`

DoR：

- 设计文档已确认
- 用户接受先做工程底座和验证门禁

DoD：

- 工程依赖和命令矩阵写清
- 后续阶段不再使用“默认检查”这类空泛表述
- `test-first` 输入明确到具体命令和目录约定

### PLAN-01A UI 参考资产回写

范围：

- 审阅 `tmp/ui/` 的视觉与布局参考
- 提炼成页面结构、组件优先级、风格约束
- 明确“代码不可复用”的实现边界

DoR：

- `tmp/ui/` 资产存在

DoD：

- 风格约束写回设计文档
- 没有把 `tmp/ui` 当作实现代码输入

### PLAN-02 创建 Chrome 扩展运行壳与页面入口

范围：

- 建立 MV3 manifest
- 建立独立扩展页面入口与基础 App 壳
- 建立基础共享目录和功能模块骨架

DoR：

- `PLAN-01` 已完成

DoD：

- 扩展能在本地构建
- Chrome 可加载扩展并打开主页面

### PLAN-03 实现书签读取、标准化图谱和本地草稿存储

范围：

- Chrome bookmarks adapter
- 草稿图谱标准化与 ID 策略
- 本地持久化：草稿、布局、展开态、撤销历史

DoR：

- `PLAN-02` 已完成

DoD：

- 能读取书签并构建规范化图谱
- 页面刷新后草稿态与布局态可恢复

### PLAN-04 实现图谱工作区核心交互

范围：

- 选中、悬浮、双击编辑
- `Enter` 新增子节点
- 删除节点及子树
- 拖拽移动
- `Ctrl+Z`

DoR：

- `PLAN-03` 已完成

DoD：

- 草稿编辑主链完整可用
- 所有交互都只作用于草稿层，不直接写回浏览器书签

### PLAN-05 实现搜索、重复 URL 聚焦和状态反馈

范围：

- 标题 / URL 搜索
- 重复 URL 聚焦
- toast、固定状态栏、错误详情展开
- 云端禁用原因提示

DoR：

- `PLAN-04` 已完成

DoD：

- 用户可快速定位节点与重复 URL
- 成功 / 失败 / 禁用态反馈清晰

### PLAN-06 实现浏览器写回确认流与本地恢复边界

范围：

- “同步到浏览器书签”警告确认框
- 草稿 -> 浏览器写回映射
- 写回失败处理
- 覆盖动作前本地最新备份语义

DoR：

- `PLAN-04`, `PLAN-05` 已完成

DoD：

- 浏览器写回只能显式触发
- `Ctrl+Z` 与浏览器写回边界清晰
- 恢复前备份规则明确且可执行

### PLAN-07 实现 WebDAV 配置、权限、版本保存与恢复

范围：

- WebDAV 配置与可用性测试
- 运行时 host permission 流
- 书签快照上传与保留最新 5 个版本
- 草稿快照上传与保留最新 5 个版本
- 从 WebDAV 恢复到浏览器或草稿

DoR：

- `PLAN-03`, `PLAN-05`, `PLAN-06` 已完成

DoD：

- 云端能力完整闭环可运行
- 未配置、无权限、测试失败时按钮禁用且原因明确

### PLAN-08 完成验收、文档回写与工作流收尾

范围：

- 跑构建 / 检查 / 测试 / 手工验收
- 回写必要 spec 与任务文档
- 准备 `finish-work` / `record-session`

DoR：

- `PLAN-02` 至 `PLAN-07` 已完成

DoD：

- 所有验证结果以 `pass` / `fail` / `not run` 记录
- 后续可直接进入 `finish-work`
