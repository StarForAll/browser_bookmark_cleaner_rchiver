## Goal

## Assumptions (Temporary)

* 由于需要直接访问浏览器书签树，产品形态大概率应转为 Chrome 扩展，而不是普通本地网页。
* 思维导图 UI 与书签树读写逻辑应分层，避免可视化组件直接耦合浏览器 API。
* 重复信息里的“完整链路唯一标识”应由节点路径或稳定节点 ID 组合生成。
* 数据流至少应拆成三层：浏览器原始书签快照、前端可编辑草稿树、显式确认后的同步执行层。
* 首版浏览器 API 适配可以先围绕 Chromium 书签能力设计，但不要把数据层写死成 Chrome-only 命名。
* Chrome 扩展官方能力可覆盖书签读写与多个 UI 容器；对大型交互界面而言，`action popup` 不适合承载主编辑体验。
* 基于当前需求，产品主方向收敛为“Chrome 扩展 + 独立扩展页面 + 云端能力”，而不是纯本地工具或纯 URL 网页服务。
* 云端能力更接近“用户自带 WebDAV 存储上的版本快照管理”，而不是 SaaS 持久化系统。
* 系统至少需要四类状态：浏览器实时数据、当前思维导图草稿、WebDAV 分类型版本快照、本地分类型单份回滚备份。
* 除了覆盖前备份外，前端编辑态还需要独立的撤销历史栈，用于节点级操作回退。
* 撤销历史应属于本地草稿态的一部分，而不是浏览器书签同步层的一部分。
* 节点识别层可以保留内部稳定 ID，但展示层应以人可理解的路径、标题、URL 和重复关系为主。

## Requirements

* 在当前项目内创建并推进可追踪的 Trellis 任务与实现产物。
* 通过实时交互收敛需求，而不是按黑盒测试场景模拟输入。
* 直接读取当前浏览器的书签信息，而不是手动输入或导入 HTML 文件。
* 以思维导图方式展示书签树，子节点可折叠和收缩到父节点中。
* 鼠标悬浮节点时显示 URL 信息；若存在重复 URL，则额外显示重复节点信息及完整链路唯一标识。
* 内部可以使用稳定 ID 进行节点识别、同步和恢复，但界面中不直接显示 ID。
* 重复节点信息采用混合模式：
  * 默认显示重复总数
  * 直接显示前 2 条重复路径
  * 剩余项通过“展开更多”查看
* 首版支持节点重命名。
* 双击节点进入编辑模式。
* 网页节点在编辑模式下可修改标题与 URL；目录节点可修改标题。
* 选中节点后按 `Enter` 用于新增子节点。
* 快捷键操作在目录节点和网页节点上保持一致。
* 新增节点时，在新增表单中选择节点类型。
* 编辑已有节点时，节点类型不可修改。
* 节点展开/折叠状态本地持久化，但不进入云端同步。
* 思维导图布局坐标本地持久化，但不进入云端同步。
* 默认初始布局需要达到美观、舒适、可直接操作的状态。
* 提供一个按钮，将当前界面自动归位到舒适的推荐布局。
* 首版只支持单一 WebDAV 配置。
* WebDAV URL、用户名、密码等连接信息由用户手动配置，并保存在扩展本地。
* 配置 WebDAV 后提供“测试可用性”按钮。
* 如果 WebDAV 未配置或测试不可用，则云端相关功能禁用，并提示用户先完成配置。
* 同步成功后的反馈采用：
  * 轻提示（toast）
  * 固定状态栏，显示最近一次同步时间、同步目标、成功状态
* 同步失败时的反馈采用：
  * 先显示人可理解的错误类别
  * 允许用户展开查看技术详情
* 首版提供基础搜索能力，可按标题或 URL 搜索节点并定位结果。
* 首版提供重复 URL 过滤/聚焦能力。
* 首版不提供多选或批量操作能力。
* 具体操作时按节点类型执行不同校验：
  * 目录节点不填写 URL
  * 网页节点 URL 不能为空
* 支持单击选中并通过拖拽移动节点到其他目录节点下。
* 支持单击选中后删除该节点及其子树。
* 删除操作直接执行，不弹二次确认框。
* 支持 `Ctrl+Z` 回退编辑历史，每次回退一个修改步骤。
* 所有快捷键操作都要在界面中明确展示。
* 默认所有新增 / 移动 / 删除操作仅修改当前思维导图草稿，不立即写回浏览器书签。
* 提供“同步到浏览器书签”按钮；点击后必须弹出明确警告框，用户确认后才执行实际同步。
* 每一次思维导图内容变化都应写入本地撤销历史。
* `Ctrl+Z` 仅回退思维导图草稿编辑，不直接回退浏览器书签同步结果。
* 首版只支持 Chrome，但代码结构要为后续 Firefox 扩展保留空间。
* 首版交互优先级不以“最小实现”为核心，而以人工操作顺滑、低摩擦为核心。
* 主界面承载在扩展独立页面 / 新标签页中，不使用 popup 作为主工作区。
* 首版前端所有用户可见文案、按钮、状态提示、错误提示、配置说明和快捷键说明均以中文展示。
* 文案组织方式要为后续多语言扩展预留空间，避免把展示文本零散耦合在组件逻辑中。
* 核心能力由扩展承载，但系统整体需要接入云端能力。
* 默认支持把当前浏览器书签树同步到 WebDAV 云端，并保留最近 5 个版本。
* 支持把当前思维导图草稿保存到 WebDAV 云端，并保留最近 5 个版本。
* 支持从 WebDAV 下载某个版本到本地，并由用户选择导入目标：
  * 浏览器书签
  * 当前思维导图页面
* 从 WebDAV 恢复到浏览器书签时，执行覆盖式恢复。
* 从 WebDAV 恢复到思维导图页面时，同样执行覆盖式恢复。
* 任何覆盖操作开始前，必须先按对象类型把当前最新状态导出到对应的本地单份备份文件。
* 浏览器书签与思维导图草稿在云端和本地都使用不同文件分别存储。
* 提供基于对应本地最新备份的还原操作。
* 全程不修改 `/ops/projects/personal/ai-coding-toolkit/docs/workflows/新项目开发工作流` 或其所在仓库内容。
